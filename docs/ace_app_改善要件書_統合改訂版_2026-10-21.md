# ace_app｜改善要件書（統合改訂版）

更新日：2026年10月21日  
対象：イベント運営・通常営業・共通UI  
目的：現場で使いやすかった既存の動線を維持しつつ、営業で判明した操作上の改善点を実装する。

> **実装前の原則**：既存の画面、DB、注文・料金・会計・日別売上の集計ロジックを調査する。類似画面・別計算処理を新設せず、既存機能を必要最小限で改修する。現行の料金体系や売上データを推測で書き換えない。

---

## 1. 共通画面・操作の改善

### UI-01｜主要機能へのボタンを並列表示

- **「来店登録」「会計」**を同じ階層で、並びのわかりやすい独立したボタンとして配置する。
- **「商品登録」「日別売上」**も同様に、独立したボタンを横に並べて表示する。
- 「同じボタン」は１つのボタンに統合する意味ではない。**同列・同程度の視認性で２つずつ並べる**という意味。
- スマホで押しやすいサイズを確保し、既存の画面遷移先につなぐ。意図のない新しい中間画面は作らない。
- 狭い画面でも文字を不自然に改行させず、左右の余白・幅を調整する。

表示イメージ：

```text
[    来店登録    ] [      会計      ]
[    商品登録    ] [    日別売上    ]
```

### UI-02｜名前検索欄に一括クリアボタン

- 名前検索入力欄の右端に「×」を置く。
- 入力文字があるときに表示し、１タップで全文字を削除する。
- クリア後は検索前の一覧に戻り、そのまま続けて別の名前を入力できる。
- クリア操作で会計や来店データが削除されることはない。

### UI-03｜来店者一覧は名前順

- 来店者一覧の初期表示順を**名前の昇順**に変更する。検索結果にも同じ順序を適用する。
- 既存データにふりがな・読みがある場合はそれを用いた五十音順を優先。ない場合は現行の名前文字列で日本語向け照合を行う（漢字名の正確な読みを推測しない）。
- 並び替えは表示だけの変更とし、来店日時・伝票・履歴データの順序そのものを書き換えない。

### UI-04｜来店者のボトムシートにも名前を表示

- 来店者をタップして開く注文・伝票用ボトムシートの**上部に来店者名**を表示する。
- 可能なら人数も添え、誰の伝票を編集しているか一目で確認できるようにする。
- 表示名は開いた来店レコードの情報を使い、別の来店者の注文と取り違えないようにする。

### UI-05｜注文メニューを３タブに統一

- 注文メニュー切替は、左から**「ドリンク」「フード」「グッズ」**の３タブとする。
- タブを切り替えても現在開いている来店者の伝票は維持する。
- 各タブで登録済みの商品を表示し、既存の注文・数量変更・取り消し・会計への反映処理を再利用する。
- 商品が登録されていないタブには、空であることがわかる簡潔な表示を出す。

### UI-06｜「テキーラ他」を「シャンパン」より先に表示

- ボトムシートの**ドリンク**内で、カテゴリの表示順を入れ替える。
- **「テキーラ他」→「シャンパン」**の順にする。他のカテゴリ順は原則維持する。
- ボトムシートを開いてドリンクタブが選択されているとき、まずテキーラ他のメニューが見えるようにする（現在のカテゴリUIに合わせ、表示位置または初期展開カテゴリを調整）。

### UI-07｜フードは価格の安い順

- フードタブ・フード一覧では、登録商品を**金額の昇順（安い→高い）**で表示する。
- 同額の商品については商品名などの安定した順序を用い、表示が毎回ばらつかないようにする。
- 商品の価格・保存順は変更せず、表示順だけを制御する。

## 2. 未会計一覧・時間表示カード

### UI-08｜カードの情報配置を見直す

**目的**：名前、人数、会計金額、経過時間、入店時刻をスマホで一目で確認できるようにする。

- 「通常営業」などの区分ラベルは、**カードの左上の枠線を少しまたぐ位置**に設置する案を第一候補とする。ただし文字や枠が切れず、タップ領域と重ならないこと。
- 左側：**名前・人数 → 大きくした金額**の順で配置。
- 右側：**経過時間 → 入店時刻**の順で配置。
- 経過時間の文字サイズ・視認性は名前・人数と同程度。入店時刻は金額に近いサイズ感。
- 主要情報の左右比率は**左４：右５を目安**に実画面で調整する。３点メニューボタン用のスペースは別途確保する。
- 入店時刻を右端に寄せすぎない。右側領域の中で自然に読める位置に配置する。
- 表示する時刻（例：`02:53`）が入店時刻であること、表示する経過（例：`1時間7分`）が滞在経過時間であることが明確になるようにする。
- 経過時間は表示上は実時間のまま。料金計算上の30分単位へ勝手に丸めて表示しない。
- カード全体の高さ、文字折返し、３点メニューとの干渉を小型スマートフォンで確認する。

参考配置（位置・サイズ感の検討用、実装の固定寸法ではない）：

```text
┌──────────────────────────────┐
│[通常営業]                    │
│                              │
│ テスト  1名       経過 1時間7分 │ ⋮
│ ¥1,200           入店 02:53   │
└──────────────────────────────┘
```

## 3. 商品登録・商品一覧

### MENU-01｜ドリンクのサイズ登録を３択に

対象：**商品登録 ＞ ドリンク ＞（例）サワー杯 ＞ サイズ選択**。

現在：`通常`・`メガ`  
変更後：**`通常`・`メガ`・`通常＋メガ`**

- 「通常＋メガ」は、**商品登録時に通常サイズとメガサイズの両方を扱うための選択肢**。１杯の注文として２サイズを同時注文する意味ではない。
- 選択後の価格入力・商品保存の仕組みは、既存の商品データ構造を確認して整合させる。両サイズで価格が異なる場合は、それぞれの単価を設定できるようにする。
- 既存の商品や会計履歴が重複・消失しないこと。

### MENU-02｜商品一覧はカテゴリ別に折りたたむ

- 商品管理の**「一覧」**を、現行カテゴリ（例：サワー杯）ごとに区切る。
- 初期状態では**すべてのカテゴリを閉じたアコーディオン**とする。
- カテゴリ見出しをタップすると、そのカテゴリの現在の商品一覧が展開する。
- 展開した内部の既存編集・削除などの操作は変えない。
- カテゴリ名が長くても不自然に折り返さず、スマホ幅に合わせる。

### MENU-03｜イベント用フードを登録・選択できるように

- イベント前または当日に、フードを**10種類以内を目安**に登録する。
- 登録項目は最低限、商品名・単価。**300円／400円／500円／900円**はよく使う価格として素早く設定できるようにし、その他の金額も入力できるようにする。
- 登録したフードは、ボトムシートの「フード」タブに反映する。
- フードをタップして数量・単価を伝票に載せ、会計と日別売上へ反映する。
- 商品編集・削除で確定済み伝票の価格や過去の会計実績を書き換えない。
- 「グッズ」も既存の商品登録・注文データと整合させる。新設が必要なら既存共通の商品処理を使い、独立の会計ロジックを作らない。

## 4. 通常営業：時間制会計

### TIME-01｜時間料金の延長単位は**30分**

- **料金計算の延長は30分単位**とする。５分・10分単位などの延長料金を新設しない。
- 基本料金、起算時刻、延長開始の条件等は**既存のルールを確認して維持**し、延長部分を30分単位で計算する。
- 「5分程度の超過をサービス」は、経過時間を消すのではなく、会計時に**30分の延長１枠分（例：600円）を請求対象から外す**運用を想定する。
- 「経過時間の表示」と「請求した時間枠」を分ける。経過時間は実際の分数で表示する。

### TIME-02｜会計対象の時間枠をスタッフが調整できるように

- 自動計算を初期値として表示し、スタッフが**30分枠の単位**で最終的な会計対象時間を変更できるようにする。
- 必要であれば「−30分」「＋30分」の操作と「自動計算に戻す」を用意する。
- 会計確定前に、**自動計算額・調整後の時間料金・差額・最終会計額**を明示する。
- 例：30分延長料金が600円で、通常は延長１枠が必要だが今回はサービスする場合、**−30分／−600円**となる。
- ドリンク・フード・グッズ等の商品代金を時間調整によって変化させない。
- **実滞在時間・自動算出した請求枠・スタッフが確定した請求枠・時間調整額**を区別して保存・集計する。

### TIME-03｜退店時刻を会計後でも訂正可能に

- 来店履歴などから退店時刻を修正できるようにする。会計済みレコードも対象。
- 入店より前の退店時刻などの不整合を防ぐ。
- 訂正後は実滞在時間を更新する一方、**確定済みの会計対象時間・金額は自動で再計算しない**。
- 変更前後の時刻と変更日時を記録する。
- 二重会計、売上の重複集計、新たな来店レコードの誤生成を防ぐ。

## 5. データと集計の基本原則

| 項目 | 保存・表示の扱い |
|---|---|
| 実入店時刻／実退店時刻 | 実際の来店記録。退店は事後訂正可能 |
| 実滞在時間 | 実時刻から計算。１分単位の表示を維持 |
| 自動算出の時間料金 | 現行料金と30分延長枠で算出 |
| 会計対象時間・延長枠 | スタッフが確定した請求内容を保持 |
| 時間調整額 | 自動料金との差額を記録 |
| 商品注文 | ドリンク／フード／グッズごとの商品・数量・注文時単価 |
| 日別売上・会計確定額 | 実際の確定売上に基づき、二重計上しない |

## 6. Codexへの実装手順・完了条件

1. **変更前に調査**：現行のナビゲーション、来店者一覧、未会計カード、ボトムシート、商品登録・一覧、料金計算・会計・売上集計の該当コードとデータ構造を把握する。
2. 既存仕様との**差分と影響範囲を示してから**着手する。新規画面や新規料金ルールの独自追加は禁止。
3. UI改修と料金・データ改修を分けて実装・確認する。既存のイベント／通常営業を壊さない。
4. 実装後、次の操作をスマートフォン幅で確認する。

**UI確認**
- 主要ボタンが「来店登録／会計」「商品登録／日別売上」の２組で並ぶ。
- 名前検索×で即クリア、来店者は名前順。
- 来店者のボトムシートに名前が表示される。
- ドリンク／フード／グッズの３タブを切り替えられる。
- ドリンク内で「テキーラ他」が「シャンパン」より先に見える。
- フードは安い順に並ぶ。
- 時間カードで名前・金額・経過・入店時刻が見やすい。

**商品管理確認**
- サイズ登録は「通常／メガ／通常＋メガ」で、登録後の各サイズ価格が正しい。
- 商品一覧は初期閉じ状態のカテゴリ別アコーディオン。
- 当日フード登録 → 選択 → 伝票 → 会計 → 日別売上がつながる。

**会計確認**
- 延長料金は30分単位。実際の経過時間は丸めず表示。
- 時間枠の手動調整で、必要に応じて30分・600円相当をサービスできる（料金額は現行設定による）。
- 時間調整で他の商品代は変わらない。
- 会計後に退店時刻を訂正しても、確定会計額は変わらない。
- 過去の会計、日別売上、既存の注文が壊れず、二重計上が発生しない。

**報告**：変更ファイル一覧、各画面の変更点、動作確認結果、未確認項目をまとめる。変更内容に関係のないデザイン刷新は行わない。
