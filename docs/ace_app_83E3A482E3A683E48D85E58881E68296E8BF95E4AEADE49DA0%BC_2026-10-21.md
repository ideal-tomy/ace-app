# ace_app｜会計画面の表示崩れ・フード画面の表示確認・時間調整UI修正

作成日：2026-10-21

## 目的

現場で利用している既存の会計アプリについて、添付スクリーンショットの表示不具合と、30分単位の手動会計時間調整の操作性を修正する。

**既存の注文・会計・認証・集計処理を壊さないこと。大規模なUI改修、機能削除、Firebase構成変更は行わない。**

## 作業開始前に必ず確認

- 起動中のアプリの実ソース、現在のGitブランチ、未コミット変更、デプロイ先を確認する。
- GitHubの `main` では `lib/features/order/widgets/order_menu_step.dart` の `_MenuTab` が `drink, food` の2種類だが、添付画面には「ドリンク／フード／グッズ」の3タブがある。**mainの状態を最新版と決めつけないこと。** 実際に起動している版で修正する。
- 今回は実装を伴う依頼。まず再現と原因を短く報告し、その後必要最小限の範囲だけ変更する。
- 営業中の実データを使ったテスト注文・会計・削除は行わない。テストはエミュレーター／開発用データで行う。

## 不具合1｜会計画面：来店者選択カードのOVERFLOW

### 再現状況

「会計」→「会計する人を選んでください」にある2列の来店者カードに、黄色と黒の警告帯と `BOTTOM OVERFLOWED BY 2.1 PIXELS` が表示される。

### 調査対象

- `lib/features/shared/person_picker_list.dart`
- `lib/features/checkout/checkout_page.dart`

GitHub `main` では `GridView.builder` の `SliverGridDelegateWithFixedCrossAxisCount(crossAxisCount: 2, childAspectRatio: 1.9)` 内に、上段の名前、営業モード、時刻を縦に並べている。必要な高さがカードの高さを超える可能性がある。

### 修正要件

- 2列表示を基本として維持し、カードの高さは内部要素が収まるように確保する。`mainAxisExtent` 等の使用を検討し、文字サイズや画面幅でも崩れないようにする。
- 名前、人数、営業モード、入店時刻を視認できること。
- 長い名前は適切に1行省略する。モード表示や時刻がカード外へはみ出ないこと。
- 小さい画面や文字拡大で2列が厳しい場合のみ1列表示などへの切り替えを検討する。
- **警告を `ClipRect` や `OverflowBox` で隠すだけの修正は禁止。** 原因となる制約・高さを調整する。

## 改善3｜30分単位の会計対象時間の手動調整

### 確認できた原因（GitHub main）

- `lib/core/billing_rules.dart` の `calcTimeCharge()` は「最初の60分が1,200円、以降は30分ごと600円」という計算を既に持つ。
- 一方、`billedMinutesChoices(autoBilledMinutes)` は `60..autoBilledMinutes` の範囲内の候補しか返さない。
- `lib/features/checkout/time_adjust_card.dart` ではこの選択肢を使用するため、入店から2分の時点で「1時間00分」しか表示されない。これは現行の候補制限によるもので、30分延長の料金式そのものが無いわけではない。

### 目標の仕様

- 実際の滞在時間と、請求に使う時間は別の値として管理する。
- スタッフが「会計対象時間」を **初回1時間、以降30分刻み** で指定できるようにする。
- 画面は `−30分` / `＋30分` ボタン、現在選択中の「○時間○分」、その時間料金を大きく表示する操作を第一候補とする。選択候補一覧を使う場合も、画面の高さに応じてスクロール可能にする。
- 自動計算時間を超える指定も必要に応じてできるようにし、**現時点の経過時間だけを根拠に選択肢を制限しない**。ただし請求の変更はスタッフの明示操作でのみ行う。
- 自動計算に戻す操作を残す。
- 時間を変更した瞬間、会計対象時間・時間料金・調整差額・合計金額を整合して更新する。
- 1人あたりの時間料金の例：60分＝1,200円、90分＝1,800円、120分＝2,400円、150分＝3,000円。人数が複数なら人数分で計算する。
- 実際の滞在時間を上書きしない。会計確定時には手動指定時間を残し、後日の売上集計で何時間分を請求したか分かるようにする。
- 調整額が「自動計算より安い」場合と「自動計算より高い」場合の両方を適切に表示・記録する。現在の `timeChargeAdjustment` は正の値を減額として扱う部分があるため、増額側に対応する表示と集計仕様を確認する。
- 請求額の正しさを先に検証し、見た目だけ候補を増やす修正にしない。
- 夜間営業の終了時刻キャップなど既存ビジネスルールを維持する。手動指定可能な最大時間は既存営業時間ルールを確認して合理的に決定し、仕様を明記する。

### 時間境界テスト

- 60分00秒 → 初回料金1,200円
- 60分01秒 → 延長扱いの有無が店舗ルールどおりであること。現在 `Duration.inMinutes` の整数分切り捨てを利用しており、60分01秒は60分となる点に注意する。
- 61分00秒 → 1時間30分ぶんの計算（1,800円／人）
- 90分ちょうど、90分超過、120分ちょうどの境界
- 手動60分、90分、120分、150分および自動に戻す
- 1名・複数名、商品注文あり・なし
- 会計を確定した後に保存値が変わらないこと
