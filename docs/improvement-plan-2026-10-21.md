## 変更前の調査

作業開始時の git status は空。アプリは Flutter Web / Firestore。データは stores/{storeId} 配下。
来店・注文・会計は CheckRepository、商品は MenuRepository、料金は billing_rules.dart、売上は SalesSummaryRepository が担当する。
注文の名前・カテゴリ・単価は items にスナップショット保存される。売上は finalAmount / eventAmountFinal / normalAmountFinal を優先し、日次締めは別の固定スナップショットを保存する。

## 実装順序

1. UI・表示順: ナビ、名前検索/ソート、カード、３タブ、フード/カテゴリ順。
2. 商品: グッズ登録を共通処理に追加、両サイズ一括保存。
3. 会計データ: 自動請求時間のフィールド追加、確定時間を常時保存、会計表示と入力検証。Firestore確定時の許可フィールドも追従。
4. 検証: 既存全テスト、追加する会計回帰テスト、スマホ幅Widget確認、静的解析、Webビルド。
5. 結果・変更一覧・未確認項目を別報告書へ記録。

実装・ローカル検証を実施済み。結果と実行できなかった確認は[実装報告](improvement-report-2026-10-21.md)を参照。

## 影響と制約

- 新画面・新料金・独立した商品会計処理は作らない。既存ドキュメントの移行・過去売上の再計算は行わない。
- 追加する billingAutoBilledMinutesFinal は新規確定伝票だけに保存。旧伝票の欠落値は推測しない。
- 時間調整は既存の減額運用を維持する（＋30分ボタンは要件上任意）。実滞在と請求枠を分ける。
- Firestoreルール変更はローカルのみ。公開・デプロイ・本番データ変更はこの作業では実施しない。
- 認証済み実DBを使う一連の操作やルールエミュレータは、利用可能な検証環境を確認し、実施できない場合は明記する。
